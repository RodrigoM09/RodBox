# PB49: reset exhausted idle streams and preserve host-token diagnostics

PB48's late sample-rate restart primed a packet but failed without any fresh retries. The reset routine only flushed busy endpoints, whereas the failure callback had already cleared busy. The exhausted retry counter and other priming state therefore survived an explicit restart.

PB49 clears priming, retry and diagnostic state for an active ISO IN endpoint on explicit reset, whether busy or idle. Busy requests retain their existing flush path. Idle resets do not flush hardware or generate a duplicate completion. Bulk, OUT and inactive endpoints are excluded; IRQ failure handling still cannot create an endless restart loop.

PB48's raw IRQ value 0xc2 combined endpoint-disabled, IN-NAK-effective and FIFO-empty. IN-NAK-effective is generated by the driver's own disable sequence, but the filter did not exclude it; these events exhausted the log budget. PB49 excludes that combination and gives NAK/IN-token-empty indications a separate eight-entry budget from completion/error indications. The formatter labels token indications separately. Explicit stream resets refresh both budgets. A raw token indication is useful positive evidence; absence still does not prove the host sent no electrical bus requests on this controller.

Validation: all 29 USB scripts passed. The production reset regression fails against PB48 and passes against PB49 for idle and busy endpoints, preserving bulk/OUT/inactive behavior and avoiding idle hardware flushes. The production logger test injects the observed 0xc2 sequence, verifies it consumes no budget, floods non-token events and confirms later tokens still log. Native ipod6g build, image checksum, artifact hashes and tracked-source identity passed.
