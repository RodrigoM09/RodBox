# PB51: keep an unsent first audio packet pending

PB50 testing captured three Lexus sessions, 28 logged retries and zero successful audio completions. Stream alternate setting 1 remained selected through each final music-transfer failure, and the host selected 44.1 kHz. Snapshots showed an enabled endpoint, raw interrupt 0x80 (FIFO empty indication), interrupt mask 0x1b and a single packet still outstanding at recovery. These observations do not establish whether the host was polling. The NAK bit requested by initialization is absent from the captured mask; no token event is not proof of absent traffic. The filesystem was clean and all 42 PB50 firmware files verified.

The startup policy nevertheless contained a reproducible stall: after eight re-arms (roughly 10 ms total in these logs), an unsent initial packet was permanently failed and the audio batch pump stopped. A later host poll could not revive that request without an explicit stream restart. PB51 removes this attempt limit only for an active, busy Classic ISO IN endpoint's single unsent first packet. Each attempt still waits for its service window and confirmed endpoint disable before flushing and rearming the same buffer. It never requests fresh PCM on this path. Diagnostic counters saturate at eight; retry and incomplete-event logging stop at that bound. Stream stop/reset still cancels pending work. Established-stream failures, inactive endpoints, consumed packets, and observed timeout/AHB errors do not qualify for continued startup recovery.

This is a candidate correction for host readiness later than the short startup window, not a proven explanation of the Lexus failure. If the host never polls, the initial packet remains pending and recovery continues at service-window cadence until cancellation; there is no busy-wait loop added. Hardware testing must confirm delivery, stable timestamps and silence/noise behavior. Missing audio-attribute acknowledgments and unsupported database requests remain unresolved and were not changed here.

Validation: all 30 USB scripts passed. The production recovery harness fails against PB50 and passes against PB51 through 10,000 missed windows, retaining the same buffer without completion/PCM advancement, counter overflow or log growth. It also checks cancellation/inactive state, delivered packets, established streams, hardware errors, frame wrap and control/bulk exclusions. The updated harness passed with AddressSanitizer and UndefinedBehaviorSanitizer. Native ipod6g build, image checksum, 42 artifact hashes and the changed driver matched the native build source (the unchanged tree uses the previously verified PB50 baseline).

Reference comparison: [Linux DWC2 gadget driver](https://raw.githubusercontent.com/torvalds/linux/master/drivers/usb/dwc2/gadget.c), particularly startup token synchronization and incomplete-transfer recovery. It does not establish support for every interrupt on the Classic's older 2.60a core. PB51's retained-buffer policy is a local adaptation, not an upstream patch.

Built only. No installation, filesystem repair, device write or music-file change was performed in this task. USB logging on the connected PB50 device remains enabled.
