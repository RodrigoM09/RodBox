# PB50: capture audio stream and recovery state

PB49 hardware testing recorded 36 retries across three sessions with zero successful audio completions. No host-token indications were logged. This does not establish whether the Lexus sent electrical IN requests: the controller may not expose them through the enabled status path. The idle exhausted-retry restart correction was not exercised by these sessions. Playback-control assertions were absent, but unsupported commands remain.

PB50 is a diagnostic checkpoint, not a confirmed audio fix. Successful iAP stream alternate-setting changes are now retained in the audio log. Before issuing endpoint disable/recovery commands, the driver records endpoint control/status, endpoint interrupt masks, frame number and global status. The global incomplete-transfer interrupt has already been acknowledged at this point. Snapshots are limited to eight groups per endpoint initialization or explicit stream reset. Packet scheduling, retry limits and PCM consumption are unchanged.

Validation: all 30 USB test scripts passed, including an AddressSanitizer/UndefinedBehaviorSanitizer harness using the production snapshot helper. It checks payloads, the eight-snapshot bound and absence of register writes. Existing reset tests check the new diagnostic budget resets. Native ipod6g build, image checksum, 42 artifact hashes and all tracked firmware source comparisons passed. PB50 has not been installed or tested in the Lexus.

The connected PB49 device had two orphaned clusters. The separately approved filesystem repair completed without formatting; the subsequent filesystem check passed. All 1,372 protected files and 42 installed firmware files verified unchanged, and 765 cached images passed structural checks. Inventory, size and modification times of 2,243 music-folder files were unchanged. No music files were written; a full music checksum scan was not repeated. USB logging remains enabled and the device remains connected.
